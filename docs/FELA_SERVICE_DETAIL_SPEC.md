# Fela Service Detail Specification

## サービス詳細の方針

サービス詳細は、Felaの中心画面です。

Felaでは、Amazon、Google、Netflix、ChatGPTなどのサービスを起点に、ログイン情報、認証コード、サブスク、AutoFill状態をまとめて管理します。

サービス詳細は、1つのサービスに関する管理センターとして設計します。ユーザーがサービス一覧からサービスを開くと、そのサービスに関する重要情報を一画面で確認できる状態にします。

認証コード画面やサブスク画面は、サービス詳細の情報を別角度から一覧化する補助画面です。情報の本体はサービス詳細に集約します。

## 画面構成

サービス詳細画面は、以下の構成にします。

```text
サービス詳細

[サービスヘッダー]
サービス名
ドメイン
状態バッジ

[ログイン]
メールアドレス / ID
パスワード
ログインURL

[認証コード]
登録状態
現在のコード（将来）
コピー（将来）

[サブスク]
月額料金
請求周期
次回更新日
支払い方法
解約URL

[AutoFill]
AutoFill状態
対応ドメイン
設定案内

[操作]
編集
削除
```

## サービスヘッダー

サービスヘッダーでは、ユーザーが今どのサービスを見ているかを明確にします。

表示項目:

- サービス名
- 主要ドメイン
- ログインURL
- サービスアイコン風の頭文字
- ステータスバッジ

ステータスバッジ例:

- 2FAあり
- サブスクあり
- AutoFill準備中
- AutoFill未登録

ヘッダーの目的は、サービス単位の状態を一目で理解できるようにすることです。

## ログインセクション

ログインセクションは、サービス詳細の中で最も重要な基本情報です。

表示項目:

- メールアドレス / ID
- パスワード
- ログインURL

方針:

- パスワードは初期非表示にする
- MVPでは生パスワードを表示せず、「保存済み」「非表示」と表示する
- コピーや表示切り替えは将来対応にできる
- ログインURLは、URL起動依存がある場合のみ開くボタンを出す
- URL起動依存がない場合はURL表示だけにする

ログインセクションは、ユーザーが最も頻繁に見る領域なので、サービスヘッダーの直下に置きます。

## 認証コードセクション

認証コードセクションでは、TOTPの登録状態を分かりやすく見せます。

MVP表示:

```text
認証コード
登録あり
```

未登録時:

```text
認証コード
未登録
あとから追加できます
```

将来的な表示項目:

- 6桁コード
- 残り秒数
- コピー
- QR再設定
- TOTP編集

認証コード画面は、このセクションをサービス横断で一覧化したものとして作ります。

## サブスクセクション

サブスクセクションでは、お金と更新日に関する情報を整理して見せます。

表示項目:

- 月額料金
- 通貨
- 請求周期
- 次回更新日
- 支払い方法
- 解約URL

表示例:

```text
月額 1,490 JPY
請求周期 毎月
次回更新 2026/07/25
支払い Apple Pay
```

未登録時:

```text
サブスク情報は未登録
料金や更新日はあとから追加できます
```

サブスク画面では複数サービスの支払い状況を一覧化しますが、情報の本体はサービス詳細に置きます。

## AutoFillセクション

AutoFillはFelaの大きな特徴なので、現在の状態を明確に見せます。

表示項目:

- AutoFill状態
- 対応ドメイン
- 設定案内

MVP表示:

```text
AutoFill
準備中
このサービスのログイン候補登録は次のステップで対応します。
```

将来的な表示例:

```text
AutoFill登録済み
amazon.co.jp
amazon.com
```

状態の候補:

- 未登録
- 準備中
- 登録済み
- 設定が必要

AutoFillの実装が進んだ後も、ユーザーが「このサービスで自動入力できるか」をサービス詳細で確認できるようにします。

## 操作セクション

操作セクションは、画面下部に置きます。

操作項目:

- 編集
- 削除

将来的な操作項目:

- 認証コードを追加
- サブスク情報を追加
- AutoFill設定
- サービス情報の更新

削除操作は危険なので、将来的には確認ダイアログを必須にします。

## デザイン改善方針

サービス詳細は、カードを増やしすぎず、セクションごとに整理します。

基本方針:

- 上部にサービスヘッダーを置く
- その下にログイン、認証コード、サブスク、AutoFill、操作を並べる
- 各セクションは白背景カードで整理する
- セクションタイトルにはアイコンを付ける
- 重要情報は大きく表示する
- 未登録状態は薄いグレーで表示する
- 登録済み状態は緑系バッジで表示する

色の使い方:

- 登録済み: グリーン
- 準備中: グレーまたは薄いブルー
- 注意: オレンジ
- 削除: 赤

初心者が見ても「何が登録済みで、何が未登録か」がすぐ分かる見た目にします。

## 情報の優先順位

サービス詳細では、上から順に重要度の高い情報を置きます。

```text
1. サービス名
2. ログイン情報
3. 認証コード
4. サブスク
5. AutoFill
6. 編集 / 削除
```

ユーザーが最も使うのはログイン情報なので、ログインセクションを最上位に置きます。

認証コードとサブスクは重要ですが、必須入力ではありません。未登録でも画面に出し、「あとから追加できます」と案内します。

## 未登録状態の見せ方

未登録状態は、空欄のままにしません。

ユーザーが不安にならないように、状態と次の行動を短く表示します。

認証コード未登録:

```text
未登録
あとから追加できます
```

サブスク未登録:

```text
未登録
料金や更新日はあとから追加できます
```

AutoFill未登録:

```text
準備中
自動入力候補の登録は次のステップで対応します
```

Felaが何を管理できるアプリなのかを伝えるため、未登録でも各セクション自体は表示します。

## サービス詳細からの導線

サービス詳細から、必要な操作へ進める構成にします。

```text
編集
  -> サービス編集画面

認証コードを追加
  -> 認証コード追加画面

サブスクを追加
  -> サブスク編集画面

AutoFill設定
  -> AutoFill設定案内

削除
  -> 確認ダイアログ
```

MVPでは、これらの導線はボタン表示または準備中表示でもよいです。

重要なのは、ユーザーが「このサービスに何を追加できるか」をサービス詳細で理解できることです。

## 完成形に近いMVP

次の実装では、以下の構成を目指します。

```text
サービスヘッダー
ログインカード
認証コードカード
サブスクカード
AutoFillカード
操作カード
```

MVPで表示する内容:

- サービス名
- ドメイン
- メールアドレス / ID
- パスワード非表示
- ログインURL
- 認証コード登録状態
- 月額料金
- 請求周期
- 次回更新日
- 支払い方法
- 解約URL
- AutoFill状態
- 編集 / 削除の入口

未登録の認証コードやサブスクもカードとして表示し、「あとから追加できます」と案内します。

## 最重要方針

サービス詳細は、Felaの中心画面です。

```text
サービス一覧
  -> サービス詳細
  -> ログイン / 認証コード / サブスク / AutoFill
```

この流れをFelaの基本体験にします。

Felaは、認証コードアプリ、サブスク管理アプリ、パスワード管理アプリを別々に並べるのではなく、1つのサービスを中心に必要な情報をまとめるアプリです。

認証コード画面やサブスク画面は、サービス詳細にある情報をサービス横断で見るための補助画面です。

どの画面から入っても、最終的には対象サービスのサービス詳細へ集約します。
