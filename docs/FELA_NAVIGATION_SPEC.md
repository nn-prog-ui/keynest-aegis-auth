# Fela Navigation Specification

## Felaの全体方針

Felaは、サービスを起点にデジタルアカウントを一元管理するアプリです。

Amazon、Google、Netflix、ChatGPTなどのサービスを追加し、そのサービスの中でID / パスワード、認証コード、サブスク、AutoFill、将来的なDigital VaultやAI Securityを管理します。

Felaの中心は「機能」ではなく「サービス」です。ユーザーはまずサービスを選び、そのサービスに紐づくログイン情報、認証コード、支払い情報、更新日、AutoFill状態を確認します。

ホーム画面には情報を詰め込みすぎず、サブスク合計などの詳細な分析は専用画面に分けます。どの画面から入っても、最終的にはサービス詳細へ自然に集約される構成にします。

## 左メニュー構成

- ホーム
- サービス
- 認証コード
- サブスク
- Digital Vault
- AI Security
- 設定

左メニューは、Felaの主要な利用目的を短く明確に並べます。サービスを主役にしつつ、認証コードやサブスクのように素早く使いたい目的別画面も用意します。

## ホーム画面の役割

ホーム画面は、ユーザーが今日見るべき情報へすぐアクセスするための入口です。

表示する情報は最小限にします。

- 最近使ったサービス
- 次に更新日が近いサービス
- 認証コードありの主要サービス
- AutoFill設定の案内
- サービス追加ボタン

ホーム画面では、サブスク合計や詳細分析を主役にしません。サブスクの金額確認や分析はサブスク画面に集約します。

ホームの目的は、ユーザーを迷わせずにサービス詳細へ誘導することです。

## サービス画面の役割

サービス画面は、Felaの中心画面です。

役割:

- 登録済みサービス一覧
- サービス検索
- カテゴリー絞り込み
- 人気サービスからの追加
- 手動サービス追加
- 各サービス詳細への入口

サービスカードに表示する情報:

- サービス名
- ドメイン
- メールアドレス / ID
- 認証コードの有無
- サブスク情報の有無
- AutoFill状態

サービス画面からサービス詳細へ遷移し、ログイン情報、認証コード、サブスク、AutoFillをまとめて管理します。

## 認証コード画面の役割

認証コード画面は、TOTPを素早く確認するための目的別ビューです。

役割:

- TOTP登録済みサービスのみ一覧表示
- 6桁コード表示
- 残り秒数表示
- コピー操作
- 対象サービス詳細への遷移

認証コードの本体データはサービスに紐づけます。この画面は、認証コードだけをすぐ使いたい場面のためのショートカットです。

## サブスク画面の役割

サブスク画面は、お金と更新日を確認するための専用画面です。

役割:

- 月額合計
- 年額換算
- 更新日順一覧
- 支払い方法別一覧
- 高額サブスクの確認
- 解約URLへの導線
- 対象サービス詳細への遷移

サブスク合計はホームではなく、この画面で見せます。ユーザーが支払い状況を確認したいときに、迷わずここへ来られる構成にします。

## Digital Vault画面の役割

Digital Vault画面は、サービスに直接紐づかない重要情報を安全に保管する場所です。

将来的な保存対象:

- マイナンバー
- 保険証情報
- 銀行関連情報
- ライセンスキー
- 秘密メモ
- 復旧コード
- 重要ファイル

初期段階では準備中の画面でもよいですが、将来的にはサービス詳細に紐づく復旧コードやバックアップコードもVault側から参照できる設計にします。

## AI Security画面の役割

AI Security画面は、ユーザーのアカウント安全性を確認し、改善提案を行う画面です。

将来的な確認項目:

- 弱いパスワード
- パスワードの使い回し
- 2FA未設定サービス
- 更新日が近い高額サブスク
- 長期間使っていないサービス
- 漏洩チェック連携候補

初期段階では「セキュリティ診断」または「準備中」として設計し、実装は後続フェーズに回します。

## 設定画面の役割

設定画面は、Fela全体の設定を管理する場所です。

項目候補:

- Face ID / パスコードロック
- AutoFill設定案内
- Keychain / iCloud同期方針
- バックアップ
- エクスポート
- 通貨設定
- 通知設定
- App Store / TestFlight情報
- プライバシーポリシー
- 利用規約

サービス単位の設定はサービス詳細に置き、設定画面にはアプリ全体に関わる項目だけを置きます。

## 各画面からサービス詳細への遷移

Felaでは、どの画面から入ってもサービス詳細へ戻れる構成にします。

```text
ホーム
  -> 最近使ったサービス
  -> 更新日が近いサービス
  -> サービス詳細

サービス
  -> サービスカード
  -> サービス詳細

認証コード
  -> TOTPカード
  -> サービス詳細

サブスク
  -> サブスクカード
  -> サービス詳細

AI Security
  -> 指摘項目
  -> 対象サービス詳細

Digital Vault
  -> サービス関連アイテム
  -> サービス詳細
```

サービス詳細は、1つのサービスに関する管理センターです。

サービス詳細に集約する情報:

- サービス名
- ドメイン
- ログインURL
- メールアドレス / ID
- パスワード
- 認証コード
- サブスク料金
- 請求周期
- 次回更新日
- 支払い方法
- 解約URL
- AutoFill状態
- 将来的なPasskey状態
- 将来的なDigital Vault関連情報
- 将来的なAI Security指摘

## ユーザーが迷わない導線

初回利用の導線:

```text
初回起動
  -> ホーム
  -> サービス追加
  -> サービス検索 / 人気サービス
  -> サービス追加画面
  -> サービス詳細
```

普段のログイン導線:

```text
ログインしたい
  -> サービス
  -> 対象サービス
  -> ID / パスワード / 認証コード確認
```

認証コードだけ使いたい導線:

```text
認証コード
  -> 対象サービス
  -> コードコピー
```

サブスクを確認したい導線:

```text
サブスク
  -> 月額合計を確認
  -> 高いサービスや更新日が近いサービスを開く
  -> サービス詳細で解約URLや支払い情報を確認
```

サービス追加導線:

```text
サービス
  -> サービス追加
  -> 人気サービス / カテゴリー / 検索
  -> 候補選択
  -> 必須情報を入力
  -> 保存
  -> サービス詳細
```

## 最重要方針

Felaで最も重要な方針は、どの画面から入っても最後はサービス詳細に集約することです。

Felaは、認証コードアプリ、サブスク管理アプリ、パスワード管理アプリを別々に並べるのではなく、1つのサービスを中心に必要な情報をまとめます。

ユーザーにとっての自然な単位は「Amazon」「Google」「Netflix」「ChatGPT」などのサービスです。そのため、Felaの情報設計もサービス単位を中心にします。

目的別画面は便利な入口として用意しますが、情報の本体はサービス詳細に集約します。
